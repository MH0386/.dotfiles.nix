# AGENTS.md

## Project Overview

NixOS dotfiles configuration using the `vic/den` flake framework with flake-parts, home-manager, and devenv.sh for development environment management.

## Repository Structure

```text
.
├── flake.nix          # Auto-generated via `nix run .#write-flake` (DO NOT EDIT manually)
├── flake.lock         # Flake input lockfile
├── devenv.nix         # Development environment config (pre-commit hooks, treefmt, language support)
├── devenv.yaml        # devenv inputs
├── devenv.lock        # devenv input lockfile (auto-updated by CI)
├── README.md          # Host bootstrap instructions (nh, nix registry)
├── modules/
│   ├── den.nix        # Den flake module integration
│   ├── dendritic.nix  # Flake-file inputs (auto-generated)
│   ├── defaults.nix   # Default config for all hosts/users
│   ├── mohamed.nix    # User-specific aspect configuration
│   ├── hosts.nix      # Host/user declarations
│   ├── hosts/         # Per-host overrides + _hardware-configuration.nix per hostname
│   ├── config/        # System config modules (nix, boot, audio, windowManager, ...)
│   └── programs/      # Program-specific modules (43 entries, many nested by category)
└── .github/
    ├── workflows/     # CI (ci.yaml) and agentic workflows (*.md + compiled *.lock.yml)
    ├── agents/        # GitHub Copilot agent definitions
    ├── skills/        # Agent skills (e.g. agentic-workflows)
    ├── aw/            # gh-aw actions lockfile
    ├── mergify.yml    # Mergify config (extends MH0386)
    └── renovate.json
```

Hosts are declared in `modules/hosts.nix` as `MohamedLaptopNixOS` and
`MohamedDesktopNixOS`; each imports
`modules/hosts/<hostname>/_hardware-configuration.nix`. Note the leading
underscore — there is no `hardware/` directory.

## Build & Deploy Commands

```bash
# Apply full system configuration (requires sudo) — pick a host
nixos-rebuild switch --flake .#MohamedLaptopNixOS

# Bootstrap path used on a fresh machine (per README.md)
nh os switch ~/.dotfiles

# Test flake validity
nix flake check

# Run devenv tests (CI command)
devenv test

# Enter development shell
devenv shell

# Regenerate flake.nix (only if using flake-file)
nix run .#write-flake

# Update flake inputs
nix flake update

# Update devenv lockfile
devenv update
```

## Code Formatting & Linting

Formatting is managed via **treefmt** configured in `devenv.nix`. Pre-commit hooks run automatically through devenv.

### Running Formatters

```bash
# Format all files (run from project root)
devenv shell treefmt

# Check formatting without applying
devenv shell treefmt -- --dry-run
```

### Active Formatters/Linters

treefmt programs (`devenv.nix` → `treefmt.config.programs`):

| Tool           | Scope                          |
| -------------- | ------------------------------ |
| nixfmt         | Nix files (`*.nix`)            |
| deadnix        | Dead code detection            |
| statix         | Nix static analysis            |
| nixf-diagnose  | Nix evaluation diagnostics     |
| yamlfmt        | YAML files                     |
| actionlint     | GitHub Actions workflows       |
| jsonfmt        | JSON files                     |
| taplo          | TOML files                     |
| xmllint        | XML files                      |
| oxipng         | PNG optimization               |

`yamllint` and `markdownlint` are **pre-commit hooks only** — they do not run
through `treefmt`.

## Nix Code Conventions

### Module Structure

Each module should be a single `.nix` file with a focused concern. Use the `den` module pattern:

```nix
{
  den.schema.conf = {
    nixos = { ... }: {
      # NixOS configuration
    };
    homeManager = { ... }: {
      # Home Manager configuration
    };
  };
}
```

Do not remove a module.
Keep nix options modular as much as possible.
Do not touch the `_hardware-configuration.nix` files under `modules/hosts/`.

### Formatting Rules

- **2-space indentation** (enforced by nixfmt)
- **No trailing whitespace** (pre-commit hook)
- **Trailing newline** at end of file
- **LF line endings** only (no CRLF)
- Use **recursed attribute sets** sparingly; prefer `let...in` or explicit references

### Import Style

```nix
# Good: Destructure at function level
{ pkgs, lib, ... }: { ... }

# Avoid: Importing everything
args: with args; { ... }
```

### Package References

```nix
# Good: Use lib.getExe for executable paths
"${lib.getExe pkgs.treefmt}"

# Avoid: Hardcoded paths or nix store references
```

## YAML Conventions

Lint/format config is **generated by devenv from `devenv.nix`** (`files` attr) and
gitignored — edit `devenv.nix`, never the generated files:

- **Max line length**: 120 characters (yamllint) / 140 characters (yamlfmt)
- **No document-start markers** (`---`)
- **Block-style sequences** (not flow) — `force_array_style = "block"`
- **No truthy value restrictions** (disabled)
- **Trim trailing whitespace**, LF endings, newline at EOF
- yamllint ignores `.github/workflows/`; markdownlint ignores `.github/`

Generated & gitignored: `.yamllint.yaml`, `.yamlfmt.yaml`, `.markdownlint.yaml`,
`.markdownlintignore`, `statix.toml`, `.github/actionlint.yaml`.

## Git Workflow

### Branch Strategy

- `main` branch is protected
- Use descriptive branch names (e.g., `feature/add-helix`, `fix/boot-config`)
- Mergify auto-merge is configured via `.github/mergify.yml` (`extends: MH0386`)

### Commit Style

Follow conventional commits:

```bash
# Format
<type>: <description>

# Examples
feat: add helix editor module
fix: correct nvidia bus ID for laptop
chore: update flake.lock
ci: adjust workflow permissions
```

### Pre-commit Hooks

All hooks run via devenv. Key hooks that may auto-fix files:

- `nixfmt` — auto-formats Nix
- `deadnix` — detects unused variables
- `statix` — suggests Nix improvements
- `yamlfmt` — auto-formats YAML

**Important**: If pre-commit hooks modify files, CI will auto-commit fixes.

## Common Gotchas

1. **flake.nix is auto-generated** — Edit `modules/dendritic.nix`, then run
   `nix run .#write-flake` to regenerate. CI also regenerates and auto-commits it
   (`ci: Update flake.nix`).
2. **Generated config files are gitignored** — `.yamllint.yaml`, `.yamlfmt.yaml`,
   `.markdownlint.yaml`, `.markdownlintignore`, `statix.toml`,
   `.github/actionlint.yaml`. Change `devenv.nix` instead.
3. **Linters run in CI, not locally by default** — `yamllint`, `markdownlint`,
   `actionlint`, `deadnix`, `statix`, `ripsecrets`, `trufflehog`, `nixf-diagnose`.
   CI auto-commits fixes as `devenv: Apply Fixes`, so expect a bot commit after
   pushing.
4. **Hardware configs live under `modules/hosts/<hostname>/`** — the file is named
   `_hardware-configuration.nix` (leading underscore). Do not edit these; they are
   imported from `modules/hosts.nix`.
5. **Two channels are tracked** — `nixpkgs` follows `nixos-unstable` and
   `nixpkgs-stable` follows `nixos-26.05` (exposed as `pkgsStable`). Use
   `pkgsStable` deliberately when you need stability.
6. **devenv.local.nix is gitignored** — Use for local overrides that shouldn't be committed
7. **`modules/` is a dendritic tree** — `import-tree` loads every `.nix` file
   automatically; filenames do not control import order. Use `flake-file`'s
   `flakeModules.dendritic` `before`/`after` hooks when ordering matters.

## CI/CD

`.github/workflows/ci.yaml` runs on push to `main`, all PRs, and daily
(`0 0 * * *`). Jobs:

- **Test** — installs Nix + devenv, runs `devenv test -v`, then
  `git-auto-commit-action` (`devenv: Apply Fixes`)
- **Nix Flake Checker** — `DeterminateSystems/flake-checker-action` (skipped on schedule)
- **Update devenv.sh** — schedule-only, `devenv update` + auto-commit
- **Generate flake.nix** — `nix run .#write-flake` + auto-commit

Agentic workflows (markdown sources compiled to `*.lock.yml`) add
`AGENTS.md Maintainer`, `Code Simplifier`, `Nix Doctor`, `CI Doctor`, and
`GitHub Agentic Workflows Upgrade`. Use `gh aw compile` after editing any
`.github/workflows/*.md`; never hand-edit the generated `.lock.yml` files.
